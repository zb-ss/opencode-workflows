# Delegated Workflow Orchestration

Plan in OpenCode. Execute across Claude Code and Gemini CLI in parallel. Review, iterate, merge — automatically.

## How It Works

The `delegate` workflow type turns OpenCode into an orchestrator that breaks features into tasks, routes each task to the best provider's CLI, executes them in isolated git worktrees, and merges the results after review.

```
You describe a feature
    ↓
OpenCode plans and decomposes into tasks
    ↓
Each task is tagged [code] or [ui]
    ↓
[code] → Claude Code CLI (opus) in worktree A
[ui]   → Gemini CLI (gemini-3.1-pro) in worktree B
    ↓  (up to 4 in parallel)
OpenCode reviews each worktree
    ↓
Failed? → re-delegate with feedback (up to 3 iterations)
Passed? → merge into feature branch
    ↓
Quality gate + completion guard on merged result
```

## Quick Start

```bash
/workflow delegate Add user authentication with OAuth and a responsive settings page
```

That's it. OpenCode handles planning, task routing, parallel CLI execution, review, and merging.

## Why Delegate?

| Approach | Who does the work | Strengths |
|----------|-------------------|-----------|
| Standard workflow | OpenCode agents (internal) | Fast, integrated, single context |
| Swarm workflow | OpenCode agents (parallel) | Speed via parallelism |
| **Delegate workflow** | **External CLIs (Claude/Gemini)** | **Best-in-class models per task, TOS-compliant, uses your existing subscriptions** |

**Use delegate when:**
- You want Claude Opus 4.6 for complex code tasks
- You want Gemini 3.1 Pro for pixel-perfect UI layouts
- You need parallel execution across multiple providers
- You want each task isolated in its own git worktree
- You already have Claude Code and Gemini CLI subscriptions

## The 8-Phase Pipeline

### Phase 1: Planning
OpenCode's architect agent analyzes the codebase and produces an implementation plan.

### Phase 2: Decomposition
The `delegation_decompose` tool breaks the plan into discrete tasks. Each task gets:
- A description and scope
- A `[code]` or `[ui]` tag (auto-detected from description or explicit)
- A provider assignment (Claude for code, Gemini for UI)
- A list of relevant files

### Phase 3: Init Files
If `CLAUDE.md` or `GEMINI.md` don't exist in the project, they're auto-generated by an LLM that analyzes the repo — detecting languages, frameworks, conventions, and build commands. This gives each CLI rich context about the project. Falls back to static detection if the LLM is unavailable.

### Phase 4: Parallel Execution
For each task:
1. A git worktree is created at `.worktrees/delegate-<task-id>/`
2. A branch `delegate/<workflow-id>/<task-id>` is checked out
3. The provider CLI is spawned with `cwd` set to the worktree
4. Up to `max_parallel` (default 4) tasks run simultaneously

**Claude Code** runs with:
```bash
claude --print --dangerously-skip-permissions --model opus --output-format json -- "prompt"
```

**Gemini CLI** runs with:
```bash
gemini --prompt "prompt" --model gemini-3.1-pro-preview --yolo --output-format json
```

Both run in permissive mode since worktrees are disposable — changes are reviewed before merging.

### Phase 5: Per-Task Review
OpenCode's `reviewer-deep` agent examines each worktree's diff:
- **PASS**: Task approved for merge
- **FAIL**: Task re-delegated with review feedback appended to the prompt

Failed tasks are retried up to `max_review_iterations` (default 3). If still failing, the task is marked failed and its worktree discarded.

### Phase 6: Merge
Approved worktrees are merged into the feature branch in dependency order using `--no-ff` (preserving task history). Conflicts are detected pre-merge and reported.

### Phase 7-8: Quality Gate + Completion Guard
Standard OpenCode quality checks run on the merged result — the same gates used by all workflow types.

## Task Routing

Tasks are automatically routed based on their description:

| Description contains | Routed to | Why |
|---------------------|-----------|-----|
| ui, layout, design, css, styling, responsive, component, figma | **Gemini CLI** | Best for visual/layout tasks |
| Everything else | **Claude Code CLI** | Best for logic/implementation |

Override with explicit tags in the plan:
```
- [ui] Build responsive navigation sidebar
- [code] Implement JWT token validation middleware
```

## Configuration

In `~/.config/opencode/workflows.json`:

```json
{
  "delegation": {
    "claude": {
      "model": "opus",
      "timeout_ms": 300000,
      "permission_mode": "dangerously-skip-permissions"
    },
    "gemini": {
      "model": "gemini-3.1-pro-preview",
      "timeout_ms": 300000
    },
    "max_parallel": 4,
    "routing": {
      "ui_patterns": ["ui", "layout", "design", "css", "styling", "component", "responsive", "figma"],
      "default_provider": "claude"
    },
    "fallback_order": ["claude", "gemini"],
    "max_review_iterations": 3,
    "auto_init_files": true
  }
}
```

### Key settings

| Setting | Default | Description |
|---------|---------|-------------|
| `claude.model` | CLI default | Model for code tasks |
| `gemini.model` | CLI default | Model for UI tasks |
| `max_parallel` | 4 | Concurrent worktree executions |
| `routing.ui_patterns` | see above | Words that trigger Gemini routing |
| `routing.default_provider` | claude | Provider for unmatched tasks |
| `max_review_iterations` | 3 | Re-delegate attempts before failing a task |
| `auto_init_files` | true | Generate CLAUDE.md/GEMINI.md if missing |

## Prerequisites

- [OpenCode](https://opencode.ai) installed
- [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code) installed and authenticated (`claude`)
- [Gemini CLI](https://github.com/google-gemini/gemini-cli) installed and authenticated (`gemini`) — optional, only needed for UI tasks
- Both CLIs available on your `PATH`

Verify readiness:
```bash
/delegate status claude --auth
/delegate status gemini --auth
```

## Simple Delegation (without workflows)

For one-off tasks that don't need the full workflow pipeline:

```bash
# Ask Claude to review code
/delegate ask claude --model sonnet "Review this diff for security risks"

# Ask Gemini to design a layout
/delegate ask gemini --model gemini-2.5-pro "Design a responsive dashboard"

# Continue a previous conversation
/delegate followup <run-id> "Now focus on error handling"

# Check recent delegations
/delegate runs 10
```

## Provider Differences

| Feature | Claude Code CLI | Gemini CLI |
|---------|----------------|------------|
| Non-interactive mode | `--print` (boolean flag) | `--prompt TEXT` (string option) |
| Auto-approve | `--dangerously-skip-permissions` | `--yolo` |
| JSON output | `--output-format json` | `--output-format json` |
| Session resume | `--resume SESSION_ID` | Not supported |
| Worktree isolation | CWD-based (we manage worktrees) | CWD-based |
| Model flag | `--model opus` | `--model gemini-3.1-pro-preview` |

## Architecture

The delegation system is composed of:

| Component | Location | Purpose |
|-----------|----------|---------|
| Delegation types | `lib/types.ts` | Shared interfaces |
| Worktree manager | `lib/worktree-manager.ts` | Git worktree lifecycle |
| Task router | `lib/task-router.ts` | Provider routing, CLI arg building |
| Init file generator | `lib/init-file-generator.ts` | CLAUDE.md/GEMINI.md generation |
| Orchestrator plugin | `plugin/delegation-orchestrator.ts` | 8 custom tools for the pipeline |
| Delegate command tool | `tool/delegate_command.ts` | Simple `/delegate` subcommands |
| Mode config | `mode/delegate.json` | Agent routing for delegate mode |
| Template | `templates/delegation.org` | 8-phase workflow template |

### Orchestrator Tools

| Tool | Purpose |
|------|---------|
| `delegation_decompose` | Parse plan into routed tasks |
| `delegation_init_files` | Ensure CLAUDE.md/GEMINI.md exist |
| `delegation_execute_batch` | Spawn parallel CLI executions in worktrees |
| `delegation_await_batch` | Poll for batch completion |
| `delegation_collect_results` | Gather worktree outputs and diffs |
| `delegation_redelegate` | Re-execute failed task with feedback |
| `delegation_merge_task` | Merge approved worktree into branch |
| `delegation_cleanup` | Remove all delegation worktrees |

## TOS Compliance

This system uses official provider CLIs with your own authenticated sessions. It does not:
- Share API keys between providers
- Proxy requests through third-party services
- Bypass authentication or rate limits
- Store provider credentials

Each CLI runs with its own auth, billing, and usage tracking.

## Troubleshooting

**CLI not found**: Ensure `claude` and `gemini` are on your PATH. Run `/delegate status --auth` to verify.

**Worktrees not cleaned up**: Run `/delegate cleanup <workflow-id>` or manually remove `.worktrees/` directory.

**Changes in wrong location**: The system uses CWD-based worktree isolation. If using `--worktree` flags directly, changes may land in the CLI's own worktree instead of ours.

**Gate enforcement failures**: If `workflow_update_gate` fails, the enforcer may not find the state file. Ensure the workflow ID matches between the supervisor and the state file. The enforcer accepts `workflowId` as a direct-lookup fallback.
